# 三分钟演示脚本

> 用途：当着人把**一条主链**走完，并且**每一屏说的话都能被代码和测试接住**。
> 这份脚本里的每一句"屏幕上会看到"都是 2026-11-14 在 1366×900 的真浏览器上逐字读出来的，不是照着代码想的。
> 不吹的部分写在 §3：哪些地方当场点了会翻车，提前说清楚。

---

## 0. 开演前 60 秒

```bash
# ① 后端（默认 8000）
#    本机若把 frontend/.env.local 的 VITE_API_BASE 指到 8001，这里就要跟着写 --port 8001
cd backend && python -m uvicorn app.main:app --port 8000
#   Windows 未激活 venv 时：.venv\Scripts\python -m uvicorn app.main:app --port 8000

# ② 前端
cd frontend && npm run dev

# ③ 演示账号（幂等：重复跑只跳过已存在的行，不会灌重复数据）
cd backend && python scripts/create_demo_user.py
#   → demo / Demo@12345（可用 DEMO_USER_PASSWORD 覆盖）
#   → 写入 1 个求职目标 + 1 份简历 + 5 个岗位 + 5 条投递（4 条在推进阶段、1 条已拒绝归档）
```

三件事先确认，省得当场尴尬：

| 要确认 | 怎么确认 | 不对时的表现 |
|---|---|---|
| 后端真的起来了 | 登录一次 | 首页三块同时显示「加载失败」= 端口不对/没起 |
| 前端打的是哪个端口 | `frontend/.env.local` 的 `VITE_API_BASE` | 同上；这条是本机真踩过的坑 |
| 当前是示例数据还是真模型 | `.env` 的 `LLM_PROVIDER` | `mock` 时首页会出现**「当前为示例数据」**提示条 —— 这是演示点，不是故障 |

演示账号已经是"有数据的人"：简历 84 分、5 个岗位匹配、5 条投递（4 条在推进阶段、1 条已拒绝归档）、1 个主求职目标。

## 1. 三分钟主链（六站）

### 0:00–0:25 · 首页「今天该做什么」

**打开**：登录后默认落在 `/home`

**屏幕上会看到**：`下午好，林知遥` · 四张指标卡（简历完整度 **84 分 / 已体检**、进行中的投递 **4 个 / 本周 +5**、最高匹配 **57 分 / 共 3 个推荐**、面试转化 **20% / 1 个面试**）· 「今日推进」里 **1 个岗位待投递** · 「下一步检查」三项全 ✓、最后一行 **资料已就绪，继续保持节奏。**

**说什么**：这不是仪表盘，是"今天该动哪一个"的入口。它已经知道我是谁（三年后端、想转 AI 应用）、手上有几份简历、五个投递各在哪一步。

---

### 0:25–0:55 · 简历中心「我的短板在哪」

**打开**：点侧栏「简历中心」→ `/resume-center`

**屏幕上会看到**：顶部 `简历版本 1 份`（PDF · 默认 · 84 分 · 上传新版本）；下面是**逐条的简历正文**；再往下是 `完整度 B` 的环形分与 **待优化**（"工作经历缺少量化成果，建议添加具体数字"）、**内容检查**六项全 ✓。

**说什么**：分数不是拍出来的——它拆成"信息是否齐全"的六项、再加一条具体待办。这里的 84 分和首页那张卡是**同一个数**，不是两套算法。

---

### 0:55–1:35 · 岗位推荐「凭什么推给我」

**打开**：侧栏「岗位推荐」→ `/jobs/recommend`

**屏幕上会看到**：`已推荐 5 个岗位`；第一张 **57 分 · Python 后端开发工程师 · 字节跳动 · 35-60K…**，下面一行证据：`技能重合: docker/mysql/python/redis; 薪资匹配; 地点匹配`，再往下是 **重合**（docker mysql python redis）与 **待补**（django kafka）两排标签；每张卡都有 `加入看板 / 查看详情 / 立即分析 / 面试准备 / 收藏 / 喜欢 / 不喜欢`。

**说什么**：推荐分带证据——**重合什么、缺什么、为什么是它**。第二张是「数据分析师 40 分」，重合只有 `python`，待补 `sql tableau hive spark`：一眼能看出"这个岗位我够不上，差在哪"。这也接住了"分数可反查"这条：同一个 (简历, 岗位) 只有一个权威分。

---

### 1:35–2:15 · 投递看板「进度在谁手上」

**打开**：侧栏「投递看板」→ `/jobs/pipeline/kanban`

**屏幕上会看到**：`本周重点：把面试机会转化为可执行的准备计划。` + 三个计数（0 待跟进 / 1 面试进行中 / 0 待决 Offer）；五个阶段各一条卡：**待投递** Python 后端（字节跳动）· **已投递** AI 大模型算法（阿里巴巴，`2天未回复`）· **笔试** 前端（腾讯，`2天未回复`）· **面试** 数据分析师（美团）· **Offer** 0；最下面是折叠的 `已结束 1 个结果已归档`（已拒绝 1）。

**这一手要演**：点「已投递」那一列的卡片（AI 大模型算法工程师）右上角的 `⋯` → 菜单里有 **移至「笔试」/ 移至「面试」/ 标记拒绝 / 放弃**。
- 说什么：**手机上没有拖拽**，所以每条卡都有一条菜单通路；拖拽和菜单发的是**同一个请求**。
- 顺带一句（懂行的人会问）：菜单里出现的目标**一定是后端允许的**，非法流转（比如从「已投递」退回「待投递」）在这里根本点不到——有一条守卫把前端那张状态机表和后端的 `VALID_TRANSITIONS` 逐键比对。
- 换「待投递」那张卡看菜单会**短一截**（只有「移至「已投递」」和「放弃」）：后端只允许它去这两处，所以「标记拒绝」也不会出现。

---

### 2:15–2:45 · 模拟面试「进场前就知道怎么问」

**打开**：侧栏「AI 模拟面试」→ `/interview/setup`

**屏幕上会看到**：三步 `01 候选人资料 / 02 目标岗位 / 03 面试场景`，当前 `技术深挖 · 10 题`；右侧 `设置本场面试 10 题 · 12-18 分钟`，题型分布 **基础能力 4 题 / 项目经验 2 题 / 行为面试 2 题 / 技术深度 2 题**；底部 `面试蓝图` 四段：**01 开场摸底 → 02 核心深挖 → 03 追问和压力点 → 04 结果复盘**。

**说什么**：这场面试是**按题量、按题型、按时间**排出来的，不是"随便问"。低分答案会触发追问（03 那一段），结束后出报告。
**别在这里点开始**——一场 10 题要 12–18 分钟，三分钟演示放不下（见 §3）。

---

### 2:45–3:00 · 求职目标「我要去哪」（收尾）

**打开**：侧栏「求职目标」→ `/targets`

**屏幕上会看到**：`当前主目标 AI 应用开发方向 · AI 应用开发工程师 · 杭州`，`1 目标方向 / 1 高优先级 / 0 关联投递`；主目标卡上是技能 `Python FastAPI RAG LLM` 与 `25-40K`。

**说什么**：这一条是"方向"，不是"简历"。同一个人的简历、推荐、面试题都该围着它转——演示数据里它和简历里的期望方向是**逐字一致**的。

## 2. 被追问时的四个硬点（都有测试撑着，可以当场翻）

1. **失败 ≠ 空**：任何一块拉不到数据，显示的是「加载失败 + 重新加载」，不是"你没有数据"。首页、简历中心、投递看板、推荐、管理侧都走这条路。
2. **加载 ≠ 空**：匹配还没回来时，「匹配概览」显示 `—`、工具条显示「正在匹配…」，不会先写一个"0 个岗位"再改成 5。
3. **示例数据与降级是"说出来的"**：`LLM_PROVIDER=mock` 时首页顶部有一条「当前为示例数据」；后端近期有降级调用时再加一条「AI 服务降级中」。
4. **点得到的一定做得到**：阶段流转有前后端同源的状态机（`tests/stageTransitionsMatchBackend.test.mjs` 解析后端字典逐键比对）。

## 3. 别点的地方（省得当场翻车）

| 别点 | 为什么 |
|---|---|
| 终态卡片（已入职/已拒绝/已放弃）上的「标记拒绝/放弃」 | 后端这三个阶段是空集，前端已按状态机把这些项**藏掉**；"撤销误点"要后端加边，属于领域决定（见 `delivery-index.md` §3 第 9 条） |
| 「开始这场模拟面试」 | 10 题 12–18 分钟，还要真 provider；三分钟里开了只能拍到第一题 |
| `/eval-reports` | 该页只统计 `rag/agent/recommend/parse` 四类报告，库里现有报表不在这个范围，页面是空的（历史证据在 DB） |
| 真 provider 下的"秒级响应"承诺 | LLM 延迟不受控；2026-11-14 的实测里主模型全程 429、兜底模型一发 JSON 用掉 16,384 token 还被截断——读数与复跑条件见 [真provider实测.md](真provider实测.md) |
| 管理侧的「定价 / 套餐」 | 定价页整族已出树（没有购买入口、也不显示当前套餐）；套餐权益没有地方可陈述 |

## 4. 收尾 30 秒：四把尺

```bash
cd backend  && python -m pytest -q          # 1576 passed / 0 failed
cd frontend && npm run test:unit            # 120 文件 / 790 条
cd frontend && npm test                     # 静态守卫 55 条（含首屏字节闸：406 kB gzip / 预算 420）
cd frontend && npm run typecheck && npm run lint && npm run format:check
```

一句话：**测试、守卫、字节、格式**四条线都是绿的，而且每一条都有一条"防空转"的反证钉着——不是"跑过了"，是"跑的东西真的在测东西"。

## 5. 如果对方问"还有什么没做"

直接翻 [`delivery-index.md`](delivery-index.md) §3 那 13 条已知限制：每一条都写了**今天的口径**和**重开条件**。
挑三条最可能被问到的：

- 看板终态没有出口（后端三个空集）——"撤销误点"需要领域决定；
- 首屏 245 kB gzip 是 Element Plus（54 个标签的传递闭包，91 个组件目录）——产品负责人已按 D90 覆盖过测量建议；
- 首页四颗文字链的触控高度 19px——WCAG 2.5.8 有"间距例外"，且它是全仓共用 primitive，改它等于改二十屏版式。
