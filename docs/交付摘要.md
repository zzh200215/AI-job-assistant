## 二、讲透一件：那个转了 733 秒的圈

这是整段里最值的一件，因为它演示了"门全绿"和"产品是坏的"能同时成立。

**现场**：`POST /analysis/full` 在 0.05 秒内回了 200 和一个任务号，然后 733 秒里什么都没发生：
进度 0%、步骤 0 条、模型调用 0 条。候选人的屏幕上是一个永远转的圈。

**根因**（不是"缺一个超时"）：`.env` 写的是 `ORCHESTRATION_BACKEND=redis_queue`，而机器上
**没有任何 worker 进程**。`submit` 只是往 Redis 里推一行，接口立刻回"已启动"。更糟的是仪表：

```
queue ok=True   queue_length=2   processing=0   dead_letter=0     ← 三个数都"正常"
```

于是系统里没有任何一个数能看出"没人消费"，它既不会失败，也不会被任何清扫收口。

**为什么"加个超时"治不了**：超时只能让转圈提前结束，说不了为什么；而当时的判据
（"最后一次活动超过 30 分钟"）对**从没开始过**的任务永远不触发——它根本没有活动行。

**改法**（四处，各自可验）：

1. worker 写心跳（90 秒 TTL，独立线程——主循环会阻塞在一次十几分钟的调用里）；
2. 收单前先问一句有没有活人，没有就 **503**，不落任务行、不发任务号；
3. 读任务状态那一跳收口"排队超 2 分钟 + 零步骤 + **确认没有消费者**"的任务，原因写进 `error_msg`；
   worker 活着时一律不动——那只是排在别人后面，判死会与真正的完成撞车；
4. 运维告警新增一条"队列没有消费者"（旧的三条规则对这个现场一条都不会红）。

**读数**（同一天，本机真栈）：没 worker 时 503 且库里 `max(id)` 不变；起 worker 后
`worker_alive=true`，同一条链 4 分 37 秒跑完 7 个步骤并收口；停掉 worker 后那条"排队 6 分钟零步骤"
的任务在下一次轮询里变成 `failed` 并带上原因。

**屏幕侧**（D9–D11、D14）：排队说排队、失败说失败，且**服务端原文不上屏**——共享轮询器刻意不把
`error_msg` 放进 `userMessage`，三条既有用例钉着这条规矩；前端按"失败 + 零步骤"这个可观察状态
说自己的话。D14 又往前一步：结果页现在自己报"这一发是几发调用换来的"，同一屏还抓出过一处把
provider 异常原文当摘要上屏的泄漏（D15 修在写入方）。

## 四、还差什么（诚实清单）

**必须知道的一条**：真 provider 那边今天还不给质量读数。主模型全程 429（最近一次彩排的 7 发调用里
1 发真实、1 发兜底、1 发截断、4 发失败），embedding 账号欠费（`type: Arrearage`），所以**推荐分数是
规则臂算的，不是模型算的**。链路本身能跑完（彩排 7/7 步、220.9 秒），但"跑完"不等于"分数可信"。
读数与三个产品级缺陷见 [真provider实测.md](真provider实测.md)。

续费之后两条命令就够：

```
python -c "from app.services.embedding_service import embed_text; print(len(embed_text('探针')))"   # 出维度＝恢复了
python scripts/measure_real_chain.py --allow-real                                                  # 结尾自己给结论
```

第二条现在会自己判定"这次读数能不能用"（`vector_score` 全空、欠费、限流、没跟到终态都会进
`blockers`），并把结论写进 `reports/measure_real_chain.json`。在此之前任何"推荐质量"的结论都不成立。
另外：D15 修的是**写入方**，库里 2026-11-16 之前写下的老记录仍带着当时的原文——那是当时真实发生的
失败，不清洗历史数据。

**部署上的一条**：`ORCHESTRATION_BACKEND=redis_queue` 时必须另起
`python -m scripts.run_orchestration_worker`；不起它，分析接口会直接 503（这是 D6 故意做的，
比回一个没人跑的任务号诚实）。升级时先升 worker 再升 web。

**产品上的一条**：投递看板的终态（已入职 / 已拒绝 / 已放弃）现在可以「撤销这一步」——但它只回退到最后
一次真实转移的那一段（凭阶段历史），**状态机里这三个仍然没有出边**；没有阶段历史的早期记录不给这颗
按钮。要想"任意回退"是另一个领域决定，没做。

其余 12 条在册限制（含为什么不动、什么时候重开）在 [delivery-index.md](delivery-index.md) §3，
逐条都带重开条件。
