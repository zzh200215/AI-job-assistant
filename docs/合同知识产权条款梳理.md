## 3. 本项目知识产权现状评估

### 3.1 自有代码

- 后端 `backend/` 与前端 `frontend/` 均为本项目自研代码（详见 `README.md` 项目结构与模块说明）。
- 无甲方专有代码混入的迹象；下一步可在 CI 中加「交付基线快照」用于比对（见 T1-2 冻结数据模型基线的同一思路，代码层面建议 git tag 一个 `delivery-v1` 基线）。

### 3.2 第三方开源组件（可商用性核查）

| 组件 | 许可证（主流） | 商用结论 |
| --- | --- | --- |
| FastAPI / Starlette / Uvicorn | MIT | ✅ 可商用 |
| SQLAlchemy / Alembic / PyMySQL | MIT | ✅ 可商用 |
| Pydantic | MIT | ✅ 可商用 |
| Vue 3 / Vite / Pinia / Vue Router | MIT | ✅ 可商用 |
| Element Plus | MIT | ✅ 可商用 |
| ChromaDB | Apache-2.0 | ✅ 可商用 |
| LangGraph | MIT | ✅ 可商用 |
| APScheduler / Redis-py / httpx / requests | MIT / BSD | ✅ 可商用 |
| WeasyPrint | BSD-3-Clause（含 LGPL 依赖，仅服务端使用） | ✅ 可商用（不随产品分发源码） |
| dashscope（阿里云 SDK） | 商用 SDK | ✅ 按官方条款使用 |

**结论**：技术栈全部为可商用开源许可证（MIT / Apache-2.0 / BSD），无 GPL 类传染性组件进入交付物，产品化不存在开源合规障碍。⭐ 建议产品化后补充一份 `THIRD-PARTY-NOTICES.md` 归档许可证文本（非本次任务范围，列入 T5-1 白皮书材料）。

### 3.3 第三方服务

- LLM / Embedding 通过 API 调用（OpenAI 兼容 / DashScope），不随源码交付，不产生知识产权问题。
- 甲方若提供了模型服务凭据，属甲方配置，产品化版本不携带。

## 4. 风险点与缓解措施

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 主合同未明确源码归属（可能约定归甲方） | 高 | 签署《技术复用补充协议》，取得明确、书面的产品化授权 |
| 竞业限制过宽（禁止进入甲方行业） | 高 | 补充协议将限制精确为「甲方所在细分市场 + 直接竞品形态」，并保留同源技术栈对其他市场的使用权 |
| 甲方数据混入产品化基线 | 中 | 产品化版本剥离甲方种子数据/配置；发布前用 `delivery-v1` 基线比对排除 |
| 保密条款与「复用通用经验」冲突 | 中 | 补充协议第五条明确：乙方不接触、不复制甲方数据；通用工程能力不在保密范围 |
| 开源许可证漂移（后续引入新依赖） | 低 | T1-3 迁移规范中同步加依赖许可证检查（可选） |
