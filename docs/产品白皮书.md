## 1. 一句话定位

**以求职者职业发展为核心、以 Agentic RAG 为引擎、支持组织协作与企业级治理的全栈智能平台**——求职者用它完成「简历诊断 → 岗位匹配 → 模拟面试 → 职业规划」的完整闭环；院校/机构/企业用它作为自有品牌的一站式就业服务平台。

## 4. Agentic RAG —— 技术差异化亮点

平台检索不采用「固定流水线把所有知识源全捞一遍」的常规做法，而是由 **Retrieval Planner（检索路由器）** 驱动：

```
用户提问 → 检索路由（LLM 决策 / 启发式回退）
        → 按需选择知识源 + 动态分配 top_k
        → 向量检索 + BM25 关键词召回 → RRF 融合 → Rerank 重排 → 置信度评估
        → 低相关片段丢弃 → 交给 Agent / LLM
```

- **检索路由**：LLM 先判断当前问题需要哪几类知识（8 类知识源：简历模板 / 岗位 JD / 面试题库 / 能力模型 / 行业报告 / 职业路径 / 薪资市场 / 转行指南），各取多少条，避免噪声膨胀；
- **多路召回**：向量语义 + BM25 关键词双通道，RRF 融合，再经 Rerank 重排；
- **置信度门槛**：低于阈值的片段直接丢弃，防止「幻觉上下文」进入回答；
- **可解释**：每次 RAG 检索引用可回看、可导出，支持质量评测报表（recall@5、MRR 等指标）。

平台在此基础上编排**多个专业 AI Agent 协作**，支持 4 种编排策略（串行 / 分层并行 / 分步执行 / LangGraph 变体），任务中心可追踪每一步执行痕迹、失败原因与质量自检结果。

## 5. 多租户 SaaS 底座 —— 一份部署、千家客户

| 能力 | 说明 |
| --- | --- |
| **租户即组织** | 一个客户 = 一个租户，行级 `tenant_id` 数据隔离，租户间数据互不可见 |
| **品牌白标** | 每租户独立 logo、主色、行业信息、自定义域名绑定；客户访问自己的专属入口 |
| **套餐体系** | `free / pro / enterprise` 三档，额度矩阵（每日分析/面试/推荐次数、导出与深度功能开关）可配置 |
| **订阅与计费** | 订阅订单、支付回调、额度每日重置；租户到期自动停用订阅、续费即时恢复，运营后台一键完成 |
| **运营后台** | 平台管理员可建租户、配品牌、配套餐、看租户级漏斗/留存/营收报表、续费、配管理员 |
| **知识库组织级共享** | 组织成员共享知识库，个人数据不自动共享；租户 + 平台公共知识双层可见性 |

**配置化交付价值**：第二个客户上线不需要改一行代码——创建租户 → 配置品牌 → 配置套餐 → 导入岗位库与知识 → 上线，全部运营后台自助完成。

## 6. 安全与合规

- **生产安全校验**：`APP_ENV=production` 拒绝弱密钥、默认密码、DEBUG 模式、mock 模型；
- **认证加固**：JWT + bcrypt 密码哈希、强密码策略与弱密码黑名单、登录/注册/重置接口限流（默认 5 次/分钟/IP）；
- **访问控制**：文件下载需登录 + 权限校验（不暴露静态目录）；JD/简历/分析记录均有行级权限守卫；
- **审计日志**：租户创建/修改/续费、管理员指派、成员变更、SSO 配置、告警确认等敏感操作全程留痕；
- **SSO**：飞书 OAuth 一次性防重放 state、凭据仅环境变量读取；
- **隐私**：个人数据概览与自助删除入口，删除简历同步清理版本记录；
- **AI 治理**：Prompt 调用追踪、token 与成本归因、AI 发布门禁（模型/版本/评测证据/审批四要素固化）；
- **备份恢复**：MySQL / uploads / 向量库备份与恢复脚本齐备。

| 形态 | 说明 | 适用 |

## 9. FAQ（常见问题）

**Q1：这套平台和招聘网站/ATS 有什么区别？**
它不替代招聘渠道，而是覆盖求职者「能力提升」环节——简历优化、匹配诊断、模拟面试、职业规划——并让机构以自有品牌提供服务。企业版可同时承担 JD 库与候选人筛选。

**Q2：白标意味着什么？**
客户拥有自己的品牌 logo、主色、自定义域名和专属入口，平台侧与客户侧的访问体验完全隔离。客户无感「这是一套 SaaS 平台」。

**Q3：数据隔离到什么程度？**
行级租户隔离，租户之间业务数据互不可见；知识库支持「租户私有 + 平台共享」双层可见。高安全客户预留独立 schema 扩展位（本期默认共享表 + 行隔离）。

**Q4：接入真实大模型需要什么？**
系统默认 mock 模式可离线演示；接入真实模型只需配置 OpenAI 兼容接口或 DashScope 的 Key 与模型名。Embedding 更换供应商时需重建向量库（有内置脚本）。

**Q5：私有化部署条件？**
Docker Compose 一键启动，需要 MySQL 8.0 与 ≥16G 内存（含向量库）；提供备份恢复脚本。安全校验在生产模式自动开启。

**Q6：能否接入我们自己的知识内容？**
可以。平台支持按 8 类知识源批量导入（txt/md/pdf/docx），可导入岗位 JD 库、题库、行业报告、薪资数据等，导入后即参与 RAG 检索。

**Q7：实施要多久？**
配置化交付：一个租户（含品牌、套餐、知识导入）约 0.5 天。第二个客户实施成本目标 ≤ 第一个客户的 40%。

**Q8：合同与版权？**
产品化改造基于甲方交付源码，已通过《技术复用补充协议》约定知识产权归属与竞业限制边界，详见 `docs/合同知识产权条款梳理.md`。
