# 数据源与演示边界说明

## 当前支持的数据来源

- 本地导入：CSV / JSON
- 演示数据：Mock 数据源、演示岗位写入接口
- HTTP API：已支持通用适配器接入，可配置 `GET/POST`、鉴权头、Query 参数、JSON 路径、分页与简单限流

## 当前不应误解为已完成的部分

- 第三方招聘平台的正式生产接入还未内置完成
- `api` 类型目前支持基础鉴权、分页与限流，但仍未内建平台级 token 刷新、复杂游标分页和高级错误回退策略
- 真实线上招聘数据的合规接入需要单独配置和验收

## 演示模式判定

以下任一情况成立，可视为演示模式：

- `LLM_PROVIDER=mock`
- `EMBEDDING_PROVIDER=mock`
- 岗位数据来自 `mock` 数据源或 `seed-demo` / `seed` 接口

## 运行时验证

系统状态页中的 `Live Mode` 只表示当前 provider 配置不是 mock，不能单独作为真实服务已经可用的证明。

- 管理员可在“系统状态”页执行 `Run minimal probe`。
- 该操作会发起 1 次最小 LLM JSON 请求和 1 次单文本 Embedding 请求，并展示成功状态、延迟和向量维度。
- 探测仅在管理员主动操作时执行，不会回显 API Key，也不会在页面加载或 CI 中自动消耗模型额度。
- 当 provider、密钥或千问兼容地址缺失时，系统状态会标记为 `misconfigured`，而不是显示为可用的 Live Mode。

## 推荐答辩口径

- 当前系统已完成“数据源管理能力”和“演示数据闭环”
- 当前 `api` 数据源已具备真实平台接入所需的基础配置能力，但仍需按目标平台补业务级适配
- 真实生产接入保留在适配器层扩展，不影响核心业务流程展示
