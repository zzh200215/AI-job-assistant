# AI 模拟面试 — WebSocket 消息协议

## 连接地址

```
ws://localhost:8000/ws/interview/{session_id}?token={jwt_token}
```

- `session_id`: 面试会话 ID（通过 REST API 创建）
- `token`: JWT 认证 Token（与 REST API 共用）

## 连接生命周期

```
客户端                           服务端
  |                                |
  |---- WS Connect (带 token) ---->|  1. 认证 + 校验会话归属
  |<-- Accept / Close(4001) -------|  2. 建立连接 / 拒绝
  |<-- {"type":"question", ...} ---|  3. 自动开始，发送第一题
  |---- {"type":"answer",...} ---->|  4. 用户回答
  |<-- {"type":"system",...} ------|  5. 回答已持久化，评分转入后台
  |<-- {"type":"question", ...} ---|  6. 下一题 / 追问（不等待评分）
  |---- GET /sessions/{id}/evaluations ->|  7. 轮询已完成评分与证据
  |          ...                    |
  |<-- {"type":"end", ...} -------|  7. 面试结束
  |<-- Close(1000) ---------------|  8. 服务端断开
```

## 消息类型总览

| 方向 | type | 说明 | 触发时机 |
|------|------|------|---------|
| C→S | `answer` | 用户回答当前问题 | 用户输入后 |
| C→S | `skip` | 跳过当前题 | 用户点击跳过 |
| C→S | `end` | 用户主动结束面试 | 用户点击结束 |
| C→S | `ping` | 心跳检测 | 每 15 秒 |
| S→C | `question` | AI 面试官提问 | 面试开始 / 每轮开始 |
| REST | `GET /sessions/{id}/evaluations` | 异步评分、证据与记忆状态 | 面试进行中轮询 |
| S→C | `evaluation` | AI 评分反馈 | 后台评分完成后回流 |
| S→C | `system` | 超时/系统提示 | 超时 / 状态变化 |
| S→C | `end` | 面试结束（含报告） | 面试完成 |
| S→C | `pong` | 心跳回应 | 收到 ping |
| S→C | `error` | 错误信息 | 任何异常 |

## 消息格式详情

### 1. 客户端 → 服务端

#### `answer` — 用户回答

```json
{
  "type": "answer",
  "content": "FastAPI 的依赖注入通过 Depends 函数实现，当路由函数声明了 Depends(...) 参数时，FastAPI 会在调用前解析依赖树..."
}
```

#### `skip` — 跳过当前题

```json
{
  "type": "skip",
  "content": ""
}
```

#### `end` — 主动结束面试

```json
{
  "type": "end",
  "content": ""
}
```

#### `ping` — 心跳

```json
{
  "type": "ping",
  "content": ""
}
```

---

### 2. 服务端 → 客户端

#### `question` — AI 面试官提问

```json
{
  "type": "question",
  "content": "请介绍一下 FastAPI 的依赖注入机制是如何工作的？",
  "metadata": {
    "round": 1,
    "total": 10,
    "category": "技术基础",
    "question_id": 3,
    "is_follow_up": false,
    "turn_id": "q-1"
  }
}
```

| metadata 字段 | 类型 | 说明 |
|:---|:---|:---|
| `round` | int | 当前题号（1-based） |
| `total` | int | 总题数 |
| `category` | string | 题目分类: 技术基础 / 项目经验 / 通用HR / 情景场景 |
| `question_id` | int | 题目唯一 ID |
| `is_follow_up` | bool | 是否为追问（默认 false） |
| `turn_id` | string | 该回答与评分证据的稳定关联 ID |

#### `evaluation` — AI 评分反馈

```json
{
  "type": "evaluation",
  "content": "{\"score\": 85, \"feedback\": \"回答全面且深入，对源码理解到位\"}",
  "metadata": {
    "round": 1,
    "score": 85,
    "completeness": 90,
    "accuracy": 85,
    "depth": 80,
    "expression": 85,
    "turn_id": "q-1",
    "async": true,
    "evidence": {"source": "answer_evaluation_agent", "answer_excerpt": "..."}
  }
}
```

| metadata 字段 | 类型 | 范围 | 说明 |
|:---|:---|:---|:---|
| `round` | int | 1- | 题号 |
| `score` | int | 0-100 | 总分 |
| `completeness` | int | 0-100 | 完整性评分 |
| `accuracy` | int | 0-100 | 准确性评分 |
| `depth` | int | 0-100 | 深度评分 |
| `expression` | int | 0-100 | 表达评分 |
| `turn_id` | string | - | 关联提问、回答与持久化评分记录 |
| `evidence` | object | - | 评分时使用的回答摘要和维度证据 |

### 异步评分查询

```text
GET /api/interview/sessions/{session_id}/evaluations
```

返回 `items`（逐题 `pending/running/completed` 状态）、`evaluation_status` 和 `memory_snapshot`。该接口只允许面试会话所属用户访问。最终报告若仍处于 `processing`，前端应继续刷新，直到后台评分全部完成。

**评分等级：**
- 85-100: 优秀 (绿色)
- 70-84: 良好 (蓝色)
- 55-69: 一般 (橙色)
- 0-54: 待提升 (红色)

**总分加权公式：**
```
overall_score = completeness × 0.3 + accuracy × 0.3 + depth × 0.25 + expression × 0.15
```

## 关闭码说明

| Code | 含义 |
|:---|:---|
| 1000 | 正常结束（面试完成） |
| 4000 | 面试已结束 |
| 4001 | 认证失败（Token 无效） |
| 4003 | 无权访问 |
| 4004 | 会话不存在 |

## 超时机制

- 每道题的超时时间为 **30 秒**（从题目发送开始计时）
- 超时后，服务端发送 `{"type": "system", "content": "⏰ 第X题回答超时（Y/3次）"}`
- 自动跳过当前题，进入下一题（`question` 消息）
- 累计超时 **3 次** → 自动结束面试（`end` 消息）

## 面试结束条件

满足任一条件即结束：
1. 所有题目完成
2. 用户发送 `{"type": "end"}`
3. 累计超时 3 次
