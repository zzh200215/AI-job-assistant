## 后端｜幂等设计：重复请求与重复扣款

- 题目：支付或下单接口被重复提交时，怎样保证不会重复扣款？
- 考察点：幂等键、唯一约束、状态机、并发去重、失败重试。
- 参考要点：客户端生成幂等键；服务端唯一索引先落记录；状态机只允许一次终态迁移；重复请求返回首次结果；失败可安全重放。
- 追问：同一幂等键的两个请求同时到达，先查后写还成立吗？

## 后端｜MySQL 事务隔离与幻读

- 题目：可重复读隔离级别下幻读是怎样产生的，InnoDB 如何抑制？
- 考察点：MVCC、ReadView、快照读与当前读、间隙锁、Next-Key Lock。
- 参考要点：快照读靠 ReadView 保证可重复读；当前读走锁；范围条件加间隙锁阻止插入；更新条件列无索引时锁范围会扩大。
- 追问：哪些 SQL 会绕过快照读，直接读最新数据？

## 后端｜慢查询定位与索引优化

- 题目：线上一条 SQL 变慢，你如何定位并优化？
- 考察点：执行计划、复合索引最左前缀、回表、排序与分页。
- 参考要点：先抓慢日志与调用量；explain 看 type、key、rows、Extra；避免函数和隐式转换；用覆盖索引减少回表；深分页改游标。
- 追问：区分度很低的列还值得单独建索引吗？

## 后端｜缓存穿透、击穿与雪崩

- 题目：缓存穿透、击穿、雪崩分别是什么，如何处理？
- 考察点：空值缓存、布隆过滤器、互斥重建、过期打散、熔断降级。
- 参考要点：穿透用空值或布隆过滤器；击穿用单飞锁重建；雪崩用随机 TTL 与多级缓存；热点可逻辑过期后台刷新；入口加熔断。
- 追问：更新数据时先删缓存还是先更库，为什么？

## 后端｜消息队列的可靠性与顺序

- 题目：怎样保证消息不丢、不重复消费，并保持顺序？
- 考察点：生产确认、持久化、手动确认、幂等消费、分区顺序。
- 参考要点：生产端确认与重试；Broker 持久化加副本；消费端手动 ack；幂等表去重；顺序靠同一分区键加单消费者；失败进重试队列。
- 追问：重试队列会不会破坏原有顺序，怎么兜底？

## 后端｜分布式事务与最终一致

- 题目：跨服务扣库存和记账，怎样保证数据一致？
- 考察点：本地消息表、TCC、Saga、补偿幂等、对账。
- 参考要点：优先接受最终一致；本地事务写业务与消息表，再异步投递；TCC 要处理空回滚和悬挂；Saga 补偿必须幂等；日终对账兜底。
- 追问：补偿一直失败时，系统应该停在什么状态？

## 后端｜高并发下的限流与降级

- 题目：突发流量打进来，怎样保护核心接口不被拖垮？
- 考察点：令牌桶、漏桶、熔断、舱壁隔离、超时预算。
- 参考要点：网关限流加服务内配额；读多写少时降级读缓存；按依赖做舱壁隔离；设置超时与重试预算；非核心功能直接关闭。
- 追问：限流阈值按什么指标定，压测和线上如何校准？

## 后端｜线上接口变慢的排障路径

- 题目：接口 P99 突然升高，你怎么在最短时间内定位？
- 考察点：变更关联、指标拆分、链路追踪、日志、止损。
- 参考要点：先看发布与配置变更；按实例、接口、依赖拆指标；用 trace 找最慢 span；日志定位异常与锁等待；必要时回滚或限流止损。
- 追问：没有分布式链路时，只有日志和监控怎么排？
